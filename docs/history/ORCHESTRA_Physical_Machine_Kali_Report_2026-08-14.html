5. How this host must load the scheduler

Do not use bare bpftool struct_ops register for this object (timer map must be pinned first). Do not boot artifacts/kernel-v6.12.96-orchestra-stage8.bzImage on this HP — NVMe is disabled in that image.

cd kernel/sched_ext
sudo ./bridge/orchestra_loader --load ./orchestra_scx_stage7.bpf.o
cat /sys/kernel/sched_ext/state          # enabled
sudo ./bridge/orchestra_bridge --status
sudo ./bridge/orchestra_loader --unload
cat /sys/kernel/sched_ext/state          # disabled

7. Next (later): benchmark

Physical scheduler comparison is intentionally not claimed in this report. A later campaign should keep the same machine, worker counts, duration, and instrumentation; prove ORCHESTRA ownership; and not treat README “~1.20× overhead” as a measured Kali result. Until identity matching is diagnosed, an ORCHESTRA bench is mostly full-switch fallback RUN.

  1. Diagnose BPF task_identity(p) vs bridge map keys / coherent snapshot.
  2. Then run existing benchmarks/real-machine/ scripts with the loader, without wiping unrelated bpffs.
  3. Prefer reduced worker counts if package temperature approaches 80°C.
