# ORCHESTRA-OS 1.0.0 research stable

ORCHESTRA-OS 1.0.0 is an immutable, reproducible **research-stable** release.
The stable surface is the observer/control plane, signal and policy validation,
diagnostics, and native package lifecycle. The sched_ext path remains an
explicitly opt-in, target-matched kernel prototype.

## Supported packages

GitHub Release assets provide all-in-one packages for x86_64/amd64 and
arm64/aarch64 on Ubuntu 24.04/26.04, Debian 13, Fedora 44, and Alpine 3.24.
The package manager owns the installed files. Installation does not compile,
load, enable, or attach a scheduler.

After installing a package, verify:

    orchestra version
    orchestra check-system
    orchestra status

The service is installed disabled. Enable it only after a target-matched
kernel build and an administrator review.

## Target-matched kernel prototype

No universal BPF object is shipped. Build an object only on the target host
against its exact running-kernel source and BTF:

    sudo orchestra build --kernel

The build fails closed when the kernel source, BTF, sched_ext headers, or
libbpf inputs do not match. orchestra enable and orchestra run remain root-only,
ownership-checked, and opt-in.

## Security and evidence boundary

Userspace signal publication provides generation, freshness, identity, schema,
and HMAC-SHA256 checks. The kernel transport is not claimed to verify that HMAC
cryptographically. Release assets include checksums, SPDX SBOMs, and CI
provenance attestations.

The sched_ext prototype has a larger privileged attack surface than ordinary
CFS operation because it requires root, BPF verification, a loader, and
kernel-specific artifacts. This release makes no claim of hard real-time
guarantees, distributed scheduling, cross-node NUMA coordination, or universal
performance improvement. Published comparisons use identical workloads and
report negative results as well as positive results.

## Verification

Download SHA256SUMS, verify each asset, and verify the GitHub artifact
attestation for the asset digest before installation. Keep the signed v1.0.0
tag and RELEASE_MANIFEST.json with any research result.
